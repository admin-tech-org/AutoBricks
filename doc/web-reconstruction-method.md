# 網頁觀察、轉換與驗收方法（草稿）

本文供使用者檢閱與測試，尚未併入 skill。本文整理 Agent 產品取得參考網址後可採用的判斷方式；章節順序方便閱讀，實作時可依問題往返，不要求固定分區、完整屬性掃描或指定工具組合。網站結構不同時，Agent 產品應重新選擇適合當站的轉換方法。

「Agent 產品」指 Claude Code、Codex 等可使用工具執行任務的 AI 助理軟體；「使用者」指指定參考網頁並接收成品的人。重建以原站的內容、外觀、RWD、互動與動畫為依據；尚未重建或驗證的部分需明列，不能因首版已接近原站就視為完成。

## 先建立對網站的理解

Agent 產品先在瀏覽器載入原站，查看首屏、逐段捲動到頁尾，再試著打開選單、切換內容與移入可操作元素。這一輪的目的，是辨識頁面有哪些內容、哪些部分隨寬度改變，以及哪些畫面需要操作或等待才會出現。

Agent 產品可以先留下簡短觀察，例如「桌面導覽在主視覺下方，捲動後固定；手機導覽在頂部；主視覺交替換圖並緩慢放大；消息可拖曳；分店依區域切換」。這些觀察同時是轉換依據與後續驗收項目，不必擴成多份重複帳冊。

接著，Agent 產品按當前問題選擇資料來源：

| 需要判斷的問題 | 適合取得的資料 | 資料如何影響做法 |
| --- | --- | --- |
| 區塊比例、構圖、文字換行是否相符 | 瀏覽器截圖 | 找出漏內容、錯圖、明顯的排版差異及值得量測的位置 |
| 元素為何偏移或尺寸不同 | DOM、`getBoundingClientRect()`、`getComputedStyle()` | 檢查父容器、字型、間距與生效的 CSS，而非直接替偏移量加補丁 |
| 手機版是否換圖、換順序或換互動 | 不同寬度的畫面、media query、可見元素與事件狀態 | 決定哪些內容共用，哪些需要獨立排列或切換方式 |
| 動畫由什麼觸發、如何變化 | 實際操作前中後的畫面、CSS、動畫或元件初始化設定 | 決定沿用原有樣式／程式庫，或重建必要的動畫邏輯 |
| 圖片、圖示與字型從何而來 | `src`、`srcset`、背景圖片、SVG、字型宣告及必要的網路請求 | 取得原始素材，保留比例、裁切與字型，不將整頁截圖當成內容 |

原始 HTML 適合取得內容與初始結構；執行後的 DOM 適合確認 lazy load、切換狀態及動態內容。輪播可能在執行時複製投影片，導覽可能插入固定定位用的空間容器，Agent 產品需辨認原始內容與執行時產物，避免把複本全部變成可編輯內容。

## 用 CDP 操作瀏覽器與取得畫面

CDP 是 Chrome 提供的控制介面。[共用 `src/browser.mjs`](../src/browser.mjs) 是 Node 工具，直接連線 Chrome，能執行 Node 的 Agent 產品都可使用。這條操作路徑不需要另外安裝 Playwright 或 MCP，指令用法見 [瀏覽器工具說明](browser.md)。

Agent 產品先確認 Chrome 已提供 CDP 連線。`browser.mjs` 的 `open` 只會在既有 Chrome 建立分頁，不會啟動 Chrome 程式。需要啟動時，可參考 [Windows 範本](../templates/launch-chrome-cdp.bat) 或 [macOS／Linux 範本](../templates/launch-chrome-cdp.sh)，將 profile 放在使用者工作目錄的 `.browser/`。Headless Chrome 可在背景渲染；需要使用者登入或觀看操作時，可使用有視窗的 Chrome。

啟動範本預設使用 9222 埠，`browser.mjs` 預設使用 9444 埠；兩端必須一致。Agent 產品可在啟動範本傳入所選埠，或透過工具的 `AUTOBRICKS_CDP` 設定連線位址。這是 AutoBricks 工具的設定，不依賴 Agent 產品專用的環境變數。

以下 PowerShell 範例假設 Chrome 已在 9444 埠執行。`$pluginRoot` 填入當次載入的 AutoBricks 根目錄；執行產物放在目前工作目錄，不寫入 plugin 快取：

```powershell
$pluginRoot = 'C:\path\to\AutoBricks'
$browserTool = Join-Path $pluginRoot 'src/browser.mjs'
$runDir = Join-Path (Get-Location).Path 'data/example'
$env:AUTOBRICKS_CDP = 'http://127.0.0.1:9444'
Invoke-RestMethod "$env:AUTOBRICKS_CDP/json/version"
node $browserTool open 'https://example.com/' "$runDir/source"
```

`open` 回傳分頁的 `target`，並保存 `browser.json` 與 `first.png`。Agent 產品把該 target 指定給後續操作，維持同一分頁的狀態：

```powershell
$target = (Get-Content "$runDir/source/browser.json" -Raw | ConvertFrom-Json).target
node $browserTool shot $target "$runDir/source/mobile.png" 0 390
```

`shot` 最後兩個參數是捲動位置與視窗寬度；此工具的視窗高度為 1000px。其他高度或操作可透過 `cdp` 子命令傳入 CDP 請求。工具提供的是操作能力，等待內容就緒、選擇分頁、截圖位置與檢查結果仍由 Agent 產品判斷。

| 動作 | 工具內使用的 CDP 方法 | Agent 產品取得的結果 |
| --- | --- | --- |
| 載入網址 | `Page.navigate` | 真實瀏覽器執行網頁後的內容與狀態 |
| 讀取 DOM／樣式、捲動或量測 | `Runtime.evaluate` | JavaScript 回傳的文字、結構或尺寸 |
| 改變視窗尺寸 | `Emulation.setDeviceMetricsOverride` | 該視窗尺寸下生效的版型 |
| 擷取畫面 | `Page.captureScreenshot` | 可存成 PNG 的圖片資料 |
| 操作滑鼠 | `Input.dispatchMouseEvent` | 點擊、移入、拖曳引發的事件與狀態變化 |

例如 Agent 產品可將下面的量測存成當次工作目錄的 `measure.js`，並以當站需要檢查的選擇器替換 `main`：

```javascript
(() => {
  const element = document.querySelector('main');
  if (!element) throw new Error('找不到量測目標，需確認當站選擇器');
  const rect = element.getBoundingClientRect();
  const style = getComputedStyle(element);
  return {
    x: rect.x, y: rect.y + scrollY, width: rect.width, height: rect.height,
    display: style.display, font: style.font, gap: style.gap,
    padding: style.padding, margin: style.margin
  };
})()
```

Agent 產品執行 `node $browserTool eval $target "$runDir/measure.js" "$runDir/measure.json"`，即可保存瀏覽器回傳的資料。`click`、`hover` 子命令則接收當站的 CSS 選擇器；特殊操作可直接使用 `cdp` 傳入請求。共用工具的原始碼提供完整參數用法。

Agent 產品再用所用產品的圖片檢視工具開啟 PNG。最近的重建使用 `view_image` 讀取圖片；其他 Agent 產品需要確認自身是否能讀取本機圖片並理解畫面。取得 PNG 檔案或輸出路徑，並不等於模型已查看圖片。

同一分頁的載入、改寬、捲動、操作與截圖需依序進行；其他操作若同時切走分頁或修改狀態，可能讓截圖逾時或讓量測失去對照基準。若共用工具對當站的 DOM 有不適用的假設，Agent 產品可改用 `eval`／`cdp`，或在當次 `data/<run>/` 撰寫小工具，不必先擴建通用框架。

## 截圖如何用於判斷與修正

Agent 產品先等待目標頁面完成載入，再確認字型、圖片及需要捲動才出現的內容。載入事件本身不保證所有動態內容都已就緒；必要時檢查元素是否出現、圖片尺寸或版型是否穩定。

整頁觀察可以使用有重疊的分段截圖，保留足以辨識文字、邊界與接縫的解析度。Agent 產品在原站與成品使用相同視窗寬高、捲動位置及內容狀態；滑鼠位置、輪播目前投影片、展開項目也會影響畫面。

截圖用來找差異，尺寸與樣式用來查原因。例如消息卡片較寬時，Agent 產品先比較外層寬度、左右 padding、卡片間距和顯示張數；所有後續區塊一起偏移時，先找前方第一個高度不同的區塊。字型載入失敗、段落預設 margin、圖片原始比例或重複初始化，都可能比局部定位更接近問題來源。

Agent 產品不需要預先讀取每個元素的所有 CSS。當同一種問題需要反覆比較時，再把相關量測寫成小程式並保留結果；修正後重驗受影響的版型或互動。

## RWD：還原原站在不同寬度下的規則

Agent 產品先比較寬、窄畫面，並查閱原站斷點附近的變化。例如 1440、768、390px 可作為初次觀察點；若選單在 1024px 切換，還需在該斷點前後檢查。觀察點的選擇依當站版型決定，三張截圖不能涵蓋所有寬度。

RWD 的判斷包括容器是否流動伸縮、內容最大寬度、欄數、gap、換行、排列順序、圖片替換與裁切，以及導覽、頁籤、固定按鈕如何改變。Agent 產品依這些行為選擇 Flex、Grid、相對尺寸、media query 或必要的互動邏輯；原站的 CSS 可用時，可篩選後沿用並限制作用範圍。

Agent 產品把版型帶進 Bricks 後，需確認原站與 Bricks 的字型基準、`rem`、`box-sizing`、元素預設 margin 和圖片顯示方式是否一致。相同 CSS 在不同頁面基礎樣式下，仍可能產生不同結果。

驗收時，Agent 產品檢查原站斷點、代表寬度與容易擠壓的中間寬度，確認文字不被截斷、圖片不變形、頁面沒有意外橫向溢出、固定導覽不遮住錨點或操作區。縮小 Chrome 視窗可以驗證響應式排列；觸控行為、實體裝置與其他瀏覽器需另外測試並分別回報。

## 動畫與互動：先看時間與狀態，再選實作方式

Agent 產品觀察動態效果時，需確認觸發條件、初始狀態、變化中的畫面與結束狀態，以及延遲、持續時間、緩動、重播或反向行為。僅看一張結束畫面，無法確認動畫已還原。

| 原站行為 | 可考慮的實作方式 | 驗收重點 |
| --- | --- | --- |
| 按鈕移入、圖片縮放、顏色淡變 | 沿用或重建 CSS transition／keyframes | 進入、離開與鍵盤焦點時的狀態，手機的對應行為 |
| 元素進入視窗時淡入或位移 | CSS 動畫搭配進入視窗的觸發邏輯，或沿用適合的原站程式 | 何時開始、是否只播放一次、初始隱藏是否正確解除 |
| 主視覺輪播、Ken Burns 緩慢縮放 | 換圖與圖片 transform 分別處理，或沿用適合的輪播元件 | 每張圖的停留時間、淡化交接、縮放起終點與重置方式 |
| 頁籤、收合、選單、彈窗 | 狀態切換、CSS 與必要的事件程式 | 開關、返回、捲動位置、焦點及窄螢幕行為 |
| 視差、隨捲動推進的畫面、複雜時間軸 | 依原站機制重建，必要時沿用原站動畫程式庫 | 以相同捲動進度比較，並測反向捲動、改寬及重新進入 |

動畫程式庫通常還需要原站的初始化設定、目標選擇器與生命週期。Agent 產品需確認相依程式如何工作，不能只下載 CSS／JavaScript 就假設效果會自動出現。原站整套框架若不適合在 Bricks 執行，可重建同等行為所需的部分；工具選擇依當前網站決定。

**量測時暫停動畫，與交付時省略動畫，是兩件不同的事。** 為比較靜態尺寸，Agent 產品可以暫停輪播、固定投影片或暫停 transform，但需記錄並恢復測試狀態。動畫驗收需重新載入正常頁面，以連續畫面、適用的錄影工具或帶時間的狀態量測，確認效果實際發生；完成一次捲動後，還要留意「第二次看得到、首次載入卻一直隱藏」的問題。若原站提供減少動態效果的設定，需區分正常與該設定啟用時的行為。

這次湯聚鍋重建保留了換圖、輪播、選單、頁籤與熱點，但未完整重建 Ken Burns 縮放和進場動畫。原因是執行時將驗收重點放在版型與主要互動，提前把其餘動畫列為差異；不能將這個案例解讀為直接使用 CDP 無法觀察或重建動畫。

## 依當站結構轉成 Bricks

Agent 產品綜合前面的資料決定轉換方式。原站 HTML／CSS 清楚時，可保留有用的類別與樣式，把文字、圖片、標題、連結及容器轉成 Bricks 元素；動態應用則可能需要依執行後的內容與狀態重組結構。大量 Canvas、WebGL、iframe 或複雜元件需個別判斷可取得的資料與可編輯方式，不能假設同一個 DOM 轉換程式能通用。

Agent 產品應合併不影響排版、選擇器與互動的多餘容器，並為主要區段及可編輯內容命名。原站 CSS 限定在重建頁面內，圖片、SVG、字型與必要腳本保留可追查的來源。仍需自訂 CSS／程式碼修改的部分，交付時明確說明。

來源 DOM 屬性也可能與 Bricks 編輯器衝突。例如本次在 Bricks 1.12.5 發現，直接保留 Elementor 的 `data-id` 會干擾元素選取；轉換後改存 `data-source-id`，再驗證編輯控制。這類問題需由當次原始碼與實測確認，不能只以公開頁正常顯示判斷可編輯性。

## 驗收以正常匯入後的頁面為準

Agent 產品完成首版後，可在本機 WordPress 新頁快速查看；最終交付仍需走 Bricks 正常匯入，並驗證匯入後的內容。格式檢查、前台渲染與編輯器操作各自能發現不同問題：

- **格式與匯入**：執行專案 JSON 驗證器，確認元素欄位、ID、父子引用；正常匯入後檢查 CSS 選擇器、素材與頁面腳本是否仍有效。
- **內容與外觀**：比對整頁內容、代表截圖、不同寬度及有差異的元素尺寸；檢查原始素材身分，不能將成功載入的佔位圖算作通過。
- **動態行為**：重新載入正常頁面，實際觸發原站觀察到的互動與動畫，核對時間、狀態切換及內容；靜態尺寸一致不能代替動態驗收。
- **可編輯性**：在 Bricks 編輯器實際選取文字與圖片，確認正確的欄位及媒體控制可用，並查看容器命名、結構與預覽。公開頁正常不代表編輯器正常。
- **交付與紀錄**：提供 JSON、WP 預覽、原站／成品截圖、素材搬移所需檔案、首版與完整驗證時間，明列剩餘差異及未測項目。問題持續存在時查明原因並回報，不能把未通過改稱已完成。

## 使用者如何比較 Agent 產品

使用者可在各 Agent 產品的新對話提供相同參考網址、重建範圍、規則版本與環境，先確認該產品能執行 Node、連線 CDP、讀取量測資料及查看 PNG，再測試完整重建。僅共用 skill 檔案，不能保證模型的畫面理解、判斷與工具操作效果相同。

本文的方法尚待 Claude Code 等產品的獨立測試。使用者可先比較原有 skill 的結果，再在另一個新對話另外提供本文，觀察新增說明是否改善動畫覆蓋、返工次數、耗時與可編輯程度；不用在測試前把所有說明加入 skill。
