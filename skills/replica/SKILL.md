做出設計師接手後編得動的成品。先親眼看網頁，再決定如何量、如何建；依當站判斷，不預設工人數、分區流程或全屬性掃描。

**怎麼做由你決定，這些結果需要交代：**

- 理解整頁內容、主要版型、窄螢幕變化與關鍵互動。截圖、DOM、computed style、原始資料各取其用；量測保留給後續查詢。
- 以 Bricks 原生元素／設定承接可編輯內容；合併沒有作用的 wrapper。原站 CSS 可視情況沿用，依這次的接手需求決定原生化程度，交代取捨。
- 固定機械工作適合寫工具；工具服務本次問題，不必先建通用框架。已有可靠資料就重用，不把每次修改變成重新探索。
- 輸出後跑 `uv run python src/validate_template.py <template.json>`；交付前驗一次 Bricks 正常匯入後的實際頁面。欄位有疑問才查 live schema 或 theme 原始碼。
- 對照代表畫面並實測主要互動與手機版；圖片核對素材身分，佔位圖也可能載入成功。漏內容、錯圖、明顯跑版優先；細小差異依使用者精度要求取捨。修改後驗相關部分即可。
- 驗證成功與視覺／互動過關分開回報；未驗證的事情照實列出。若持續調整卻無改善，查原因或交代限制，不無限磨同一處。

**本機 Bricks 寫入注意**

可用 `docker/push-template.php`，不帶 PAGE_ID 會建立新頁。給模板及容器暫存檔本次獨立名稱，記住回傳頁號後才續修。原有頁面與全站設定需避免意外覆蓋。

元素 id 用唯一的六碼小寫英數字、至少含一個數字；parent／children 雙向一致。自訂 CSS 使用實際 `#brxe-<id>`。圖片保留比例。輸出完整模板的 title、type、templateType、content，使用 global classes 時包含其定義。

處理 JSON 匯入或 SVG 素材時，按需查 [Bricks 匯入備忘](references/bricks-import.md)。新增經驗先判斷適用範圍，特定版本／網站的做法留在備忘或當次紀錄。

交付模板 JSON、可開啟的 WP 預覽、代表截圖與簡短測試紀錄。首次工具建置時間和實際轉換／修正時間分開記，讓速度比較可解讀。
