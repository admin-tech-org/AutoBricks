# cleanroom — 把網頁復刻成「結構乾淨的原生 HTML/CSS/JS」

**一句話**：做一份**乾淨**且**忠實**的原生網頁復刻。它不綁任何 builder，能自己站著跑，
是之後轉 Bricks（或任何工具）的來源。

> **名詞**
> - **原站**：目標網頁。Claude 開著它的分頁＝**原站分頁**。
> - **復刻頁**：我們寫的那份乾淨 HTML，跑在本機靜態伺服器。它的分頁＝**復刻分頁**。
> - **收斂**：改到 pixel diff 為 0。
> - 每一步都是 Claude 做（host 與 band subagent 都是 Claude 的分身）。

## 這一段的職責邊界（全篇最重要，違反了後面全白做）

| | 要求 |
|---|---|
| **忠實** | **不准失真。** 整頁 pixel diff = 0。 |
| **乾淨** | DOM 層次淺、命名可讀、沒有框架殘渣、沒有無意義包裝層。 |

**「乾淨」講的是結構，不是外觀。** 乾淨 ≠ 長得不一樣——**像素必須一模一樣**。

**失真只准發生在下游。** 下游（Bricks 等）做不到的事，是**下游**的損失，在**下游**才發生。
**絕不准在這一段預先妥協**——「反正 Bricks 也做不到，這裡就先隨便做」是**明確禁止**的。
這一段乾淨且忠實，下游的失真才可歸因（一眼看出是「我沒做好」還是「工具做不到」）。

## 權威：整頁 pixel diff

**這是唯一的驗收關卡，因為它沒有白名單。**

手工挑選的屬性名單（「這幾個屬性很重要」）必然漏——瀏覽器暴露 700+ 個 computed 屬性，
挑幾十個就是在賭「我猜中了重要的」。**pixel diff 不挑，它看全部。**

- 我們跟原站**是同一個平台**（都是瀏覽器裡的 HTML/CSS）→ 沒有理由不能 0 差異。
  達不到 0 就是還沒做完，不是「平台差異」。
- 逐屬性 diff（`getComputedStyle` 相減）與 DOM 走訪**是除錯工具，不是關卡**——
  pixel diff 說「這裡不一樣」，你用它們查「為什麼」。
- 反鋸齒噪音：文字／曲線邊緣可能有 1–2 階通道差。**容差要落檔講清楚**（最大通道差、
  不同像素數），不准用「看起來一樣」帶過。

**pixel diff 抓不到的只有兩類**，各有對策：
1. **會動的東西** → 兩邊都把動畫停在同一相位再比（`animation-play-state` / `seek`）。
2. **行為** → 見「行為清冊」，那是唯一的第二本帳。

### ⚠️ 達不到 0 時，不准用「退回去不塌」來換

**0 和「乾淨」會互相拉扯，這是這份 skill 最危險的地方。**
塌掉一層包裝若造成 1px 位移，拿到 0 最省事的辦法就是「那就不要塌」——
於是結構越做越像原站的 DOM，**兩個要求裡你只剩一個**。這是**明確禁止**的。

達不到 0 時，**照這個順序**處理：
1. **先假設那層其實有視覺。** 最常見的真相就是它有你沒看到的東西
   （`overflow`、`stacking context`、`flex-shrink`、`min-width:auto`、
   `line-height` 造成的行盒、`margin` 不合併…）。回去量，不要用眼睛看。
2. **再假設是幾何表達的問題。** 同樣的版面可以用不同寫法達成；
   少一層巢狀時分數像素的捨入可能不同 → 換個寫法（明確寬度、`gap` 換 `margin`…）。
3. **前兩者都不是，才落檔回報**：不同像素數、最大通道差、bbox、根因假說。
   **由 host 裁示**，band 不准自己決定「這樣就好」。

**「把塌掉的層加回去」永遠不是答案。** 那是拿乾淨換忠實，而這一段兩個都要。

> 為什麼不乾脆放寬成「容差 2 階以內」：**容差需要判斷，而判斷正是長 context 下最先壞掉的東西**
> ——那正是這份 skill 用 host＋subagent 在解的問題。**0 不需要判斷。**
> 實證：band 1（marquee）在塌掉 62% 節點的前提下，6 個相位全部拿到 0、零容差。
> 0 是做得到的，不是理想值。

## 四條鐵律

1. **照觀察複刻，不照原始碼意圖複刻。**
   class／JS 裡看到的效果，必須在**原站實測**確認真的發生。實測沒發生的是**死碼**，
   記 excluded ＋理由。**也絕不憑印象補「這種元件通常會有」的效果**（跑馬燈通常會 hover
   暫停、手風琴通常會轉箭頭——原站不做，我們就不做）。
2. **不准用眼睛猜數字。** 所有數值來自 `getComputedStyle` 實測。「看起來像 18px」是錯的。
3. **先捲再點。** 動手前先判互動模型（見 Phase 2 ②）。判錯＝整區重寫，不是改 CSS 能救的。
4. **plugin 目錄唯讀。分析工具一律 `tmp/` 現寫。**
   為什麼：分析的輸入是「任意網站」＝無界，任何預先寫死的分析程式都補不完，
   而**發行出去的 plugin 是改不了的**（唯讀＋marketplace 更新會整包蒸發）。
   **這份 skill 必須在「plugin 一行都不能改」的前提下跑完任何網站**——
   做不到就是 skill 壞了，不是工具缺一個屬性。

## 執行模式：host 派工、一區一個全新 subagent

> **為什麼**：同一條 context 從頭做到尾，開頭載入的規則會被越來越長的對話稀釋——
> 實測：前兩區最嚴謹，越往後越漏，甚至發明原站沒有的效果。

- **host**：做 Phase 0／1（產物全部落檔）、逐區派工、驗收。自己的 context 長得慢。
- **一區＝一個全新 subagent**。**不可用 fork**（會繼承 host 的長 context，等於白做）。
- **依序執行、絕不並行**：CDP 瀏覽器只有一個；頁面由上往下長。
- **派工時必須注入**：① 先讀本 SKILL.md 全文；② 本區資訊（區 key、節點範圍、原站與復刻頁
  URL、`tmp/` 現有工具清單）；③ 檔案慣例（只動自己的區）；④ **分頁慣例：動手前自己
  `browser_tabs list` 確認角色，不信任前一手留下的狀態**；⑤ 收帳定義。
- **host 驗收**（便宜、不重做工）：讀該區 ledger → `Read` 該區 pixel diff 圖與數字 →
  **自己抽驗一個數字**（重跑一次 diff 或量一個盒）。不過關 → `SendMessage` 叫**同一個**
  subagent 補。**回報文字不算數，落檔的工件才算。**

### 分工：band 顧忠實，host 顧乾淨

**band subagent 只負責「忠實」（pixel diff = 0）。「乾淨」由 host 驗收，也由 host 動手優化。**

為什麼不交給 band：
- **乾淨是跨區的性質，band 看不到。** 它只有自己那一區的視野；15 個 band 各自優化＝15 種不同寫法
  （同一顆 icon 有人 inline、有人 `<use>`、有人 `<img>`），合起來反而更髒。
- **只有 host 知道下游。** 這份 HTML 的唯一讀者是下一段的轉換器；哪種寫法好轉，band 無從判斷。
- 讓 band 一邊追像素一邊想全域結構，等於逼它做它沒有資訊做的決定。

**host 的乾淨度 gate（要用數字，不是印象——跟 pixel diff 同一個標準）：**
- **重複率**：同一段 markup（尤其 SVG 的 `<path d>`）出現幾次？unique 幾個？
  重複的字元數佔全檔多少？→ 高重複＝該抽成 `<symbol>`／`<use>`／共用 class。
- **最長行長度**：一行上千字元＝人不可讀。
- **DOM 深度與元素數**：對照原站子樹，塌掉多少？
- **idiom 一致性**：同一件事全頁只准一種寫法。

**時機**：一區收帳後由 host 檢查；要重構就 host 自己改，改完**重跑該區 pixel diff，
不是 0 就退回**。跨區的模式（icon sprite、共用 class）**越早定越好**——晚了會被複製 N 次。

## Phase 0 — 環境

1. **CDP Chrome**：
   ```bash
   PORT=$(grep -s '^CDP_PORT=' .browser/cdp.env | head -1 | cut -d= -f2 | tr -d ' \r'); PORT=${PORT:-9222}
   curl -s "${PLAYWRIGHT_CDP_URL:-http://127.0.0.1:$PORT}/json/version"
   ```
   連不上就跑 `.browser/` 的啟動腳本。
2. **批次編號** `<年月日-時分秒-站名>`；產物放 `data/<id>/`，復刻頁放 `data/<id>/site/`。
3. **靜態伺服器**（服務 `data/<id>/site/`，背景跑，固定埠）。**不要用 `file://`**
   ——字體與 CORS 會出怪事。
4. **校準**：resize 1440 後**必驗 `window.innerWidth`＝1440**（螢幕縮放要按 dpr 補償）；
   每次導航後重驗。

## Phase 1 — 全站基礎（host 做，序列，不可跳）

1. 導航原站 → 逐屏捲到底（觸發延遲載入）→ 回頂。
2. **基準截圖** 1440／768／375 各一張全頁，存 `data/<id>/`。
3. **🎬 頁級行為掃描**（慢捲一輪）：header 捲動後變不變？進場動畫？`scroll-snap`？
   視差？smooth-scroll 庫指紋（`.lenis`／`.locomotive-scroll`）？持續動畫清冊
   （`getAnimations()`）？逐筆記進 `plan.json` 的 `page_behaviors` 並**歸屬到區**。
4. **⭐ 資產下載（不下載就等於沒復刻）**：掃全 DOM 收集並**真的下載**到 `site/assets/`：
   - `img.currentSrc`（**不是** `img.src`——要的是「實際載入的那張」）、`srcset` 的每個候選
   - `<video>` 的 `src` 與 `poster`
   - 每個元素 computed 的 `background-image` 裡的 URL（漸層不算）
   - favicon、`<link rel=preload as=font>` 與 `@font-face` 的 woff/woff2
   - **inline `<svg>`**：抽出來、去重、存成具名檔（依視覺功能命名：`icon-star.svg`）
   下載器寫在 `tmp/`。**引用一律改成本機相對路徑**——復刻頁斷網也要能完整渲染。
5. **tokens**：字體（**量實際生效的字族**，不是 stack 第一個——`ui-sans-serif` 這類
   關鍵字瀏覽器不一定解析）、色票、內容區寬度。
6. **切區**：把整頁切成幾個「區」（一個頂層子樹＝一區），寫成工作清單。
   > 走訪 DOM 的工具**在 `tmp/` 現寫**。要點：完整 class 比對＋連續兄弟才算重複
   > （前綴縮寫會把不同 section 誤併）；「有視覺」必須含 `background-image`
   > （漸層／網點的包裝層不可塌）；自檢 `walked + skipped == domTotal`。
7. **祖先鏈也要處置**：`body → wrapper → main` 這條在 section 之上的鏈常帶**頁級背景**
   （網點、底色），會透過透明區塊透出來。逐一查它們的 `background-color/image`。
8. 建 `site/index.html` ＋ `site/style.css` 骨架（含 tokens、頁級背景、字體）。
9. 寫 `data/<id>/plan.json`（tokens、區清單、每區狀態、`page_behaviors`、資產清單）。

## Phase 2 — 一區一區做（band subagent 執行）

**① 萃取（實測，不目測）**
- 對這一區的每個節點跑 computed 抽取（工具 `tmp/` 現寫）。**數值全部來自實測。**
- 有狀態的元件要抽**全部狀態**：tab／輪播**逐個真點擊**，每個狀態各抽一次，
  記清楚「哪個內容屬於哪個狀態」。

**② 先判互動模型，才准動手**
1. **先不要點。** 慢慢捲過這一區，看有沒有東西**自己**變。
2. 有＝scroll-driven：查明機制（IntersectionObserver／scroll-snap／sticky／
   animation-timeline／scroll listener）。
3. 捲動都沒反應，才輪到 click／hover 掃（**用真滑鼠**）。
4. 結果**必填**進 plan.json：`互動模型: static｜click｜scroll｜time`（可複合）。

**③ 寫 spec（沒寫 spec 不准動手寫 HTML）**
落檔 `tmp/spec-<band>.md`：結構樹、每個元素的實測數值、資產路徑、行為規格
（觸發→實測效果→做法）、互動模型。**這份 spec 是「我打算怎麼做」的白紙黑字，
它讓下一步變成執行，而不是邊寫邊想。**

**④ 寫乾淨的原生 HTML/CSS**
- 結構：語意標籤、可讀 class 名、**塌掉沒有自己樣式的包裝層**、重複的做成一組 class。
- **但是：塌任何一層之前，先確認它沒有視覺**（背景、邊框、間距、overflow、
  stacking context）。**塌錯了 pixel diff 會告訴你。**
- CSS 寫 `site/style.css`，用 Phase 1 的 tokens。行為寫 vanilla JS（自包含）。

**⑤ 對照（權威在這裡）**
- **pixel diff**：原站與復刻頁**同一捲動位置**各截一張 → 逐像素比 → **收斂到 0**。
  會動的先停在同一相位。容差落檔（不同像素數、最大通道差）。
- **行為實測**：行為清冊逐筆用**真滑鼠**驗（hover 前後量、等輪播動、點了看展開），
  跟原站的實測效果比。過的標 `verified`。
- diff 不為 0 → 用逐屬性 diff／DOM 比對查原因（**除錯工具**）→ 改 → 重比。

**⑥ 收帳（兩條，缺一不可）**
- **pixel diff**：這一區 = 0（或明列容差＋數字）
- **行為清冊**：沒有任何 `todo`（全是 verified 或 excluded ＋理由）

兩條都過，plan.json 該區才能標 `done`。

## Phase 3 — 平板／手機（桌機全 done 才開始）

先 768 整輪、再 375 整輪。兩個分頁都 resize＋重新校準。
一樣 pixel diff 收斂到 0，並確認無水平捲軸。

## Phase 4 — 收尾

1. **整頁** pixel diff 三個寬度各一次（不是逐區，是整頁——區與區的銜接只有整頁看得到）。
2. 復刻頁**斷網自測**：關掉網路重載，資產必須全部還在（有外連＝資產沒下載乾淨）。
3. 清 `tmp/`、關本次分頁、專案根不留垃圾。
4. **回報**：pixel diff 三個寬度的數字、行為清冊逐筆結果、資產清單、
   `site/` 路徑、待人工清單。
